## Auth saga — what we know and what's still open

### What we tried (in order)

1. Set `NEXTAUTH_SECRET` (build was failing on env validation)
2. Fixed `NEXTAUTH_URL` (it had been set to literal placeholder text)
3. PR #126: added `trustHost: true` → fixed `MissingCSRF` error
4. PR #127: bound `secret:` explicitly in authConfig (`AUTH_SECRET ?? NEXTAUTH_SECRET`)
5. Regenerated secret as **hex** (no `+/=` chars that might URL-decode in transit)
6. Set the env var via CLI (`vercel env rm` / `vercel env add`) to bypass the web UI
7. Added a parallel `AUTH_SECRET` env var (NextAuth v5 canonical name)

### What we observed

- First sign-in succeeds (POST /api/auth/callback/credentials → 200, lands on /insights)
- The very next navigation triggers `JWTSessionError: no matching decryption secret`
- This means: the function instance that issued the cookie used secret **X**, and a different function instance reading the cookie has secret **Y**
- Re-tries on the form submission also fail — `MissingCSRF` reappeared briefly until trustHost landed

### What's still open

The leading hypothesis is that **middleware (Edge runtime) and serverless
functions (Node runtime) load `NEXTAUTH_SECRET` differently** on Vercel
— so cookies signed in one runtime can't be decrypted in the other.
Alternative: per-instance auto-secret generation despite the explicit
`secret:` binding.

### Workaround

`DISABLE_AUTH=true` env flag (from PR #128). When set, three points
short-circuit:

- `middleware.ts` — let every request through
- `AccessGate` — render children regardless of role
- `requireAuth` — return synthetic admin user (so writes work)

Every bypass logs a `console.warn`, so the runtime logs are loud while
this is on. Take it off the moment auth is fixed.

### Next session plan — auth debug page

The user's idea: stand up a dedicated `/auth-debug` page that **bypasses
DISABLE_AUTH for itself** and exposes diagnostics — `NEXTAUTH_SECRET`
length at runtime, cookie names seen on the request, raw cookie value,
JWT decode attempt result, `await auth()` output. Iterate there without
affecting the rest of the app (which stays in public mode for now).
